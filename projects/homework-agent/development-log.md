# 开发过程记录

本文记录设计变化、实际故障和证据边界。当前方案见[项目说明](README.md)；不包含学校账号、真实课程内容或核心实现。

## 1. 先建立最小读取链路

先完成平台无关的日期解析、去重、历史记录和中文报告，再接入课程平台。通过本地模拟服务验证分页、状态判定与失败处理，测试数据与真实历史隔离。

站点侦察确认教学门户与课程平台不是同一层。未授权接口可达只能证明端点存在，不能证明个人账号读取权限。早期文档将这两种证据混在一起，现已修正。

## 2. 接入方式从令牌优先调整为浏览器会话

早期实现提供访问令牌路径，但它不是用户选择的前提。实际需求是复用安全会话，由用户本人处理学校认证。

最终采用专用浏览器建立会话、同站点结构化接口读取课程。没有保存密码或自动处理验证码，也没有把日常浏览器的个人配置复制给自动化程序。内置浏览器控制连接不稳定后，改用项目自己的专用浏览器入口。

关键认识：浏览器认证和 API 读取可以组合；访问令牌不会消除凭据到期、权限和撤销问题。

## 3. 修正登录交互与错误诊断

最初需要用户看到课程后回到命令窗口按回车，这让“页面登录成功”和“程序验证成功”混在一起。

登录流程改为有界等待：检测进入目标平台后，用只读身份接口验证，再在同一会话读取作业。正常成功流程不再需要终端回车。失败保留可排查状态，诊断只记录阶段、类别和必要协议摘要，不记录响应正文或凭据。

## 4. 解决成功响应被误判为请求失败

实际学校页面已登录，接口也返回成功状态，但客户端处理响应时仍抛错。脱敏诊断将问题定位到响应头转换，而非密码或验证码。

浏览器请求库把重复 Cookie 响应头合并为包含换行的值；再次交给另一套响应头构造器时被拒绝。本地 HTTP 服务复现同类响应，修复前出现相同故障，调整响应头读取方式后回归通过，随后真实课程读取成功。

这一轮避免了继续要求用户重复登录来处理一个客户端兼容性问题。

## 5. 纠正会话持久化测试的假成功

早期本地服务对每次请求都重新下发 Cookie。第二个浏览器访问后有 Cookie，并不能证明它恢复了第一个浏览器的登录状态。旧文档“持久化已证明”的结论因此撤回。

学校实际重开测试也发现会话未保留。随后增加 Windows 当前用户加密会话保存，遵守目标域、原始到期时间和本地保存时限。

修订后的测试只在首次登录发 Cookie，第二个全新配置的浏览器直接访问受保护接口，并检查加密文件不含测试明文、跨源与超时恢复被拒绝。该本地测试通过后，再完成学校端独立进程认证与重复扫描验证。

真实验证需要匹配运行身份和权限环境；受限环境下的认证失败与正常当前用户环境下的成功分别记录，不能由一次成功推断任意调度环境可用。

## 6. 报告与状态的可靠性修正

- 提交状态按明确规则判定，避免将未提交状态误当已提交。
- 平台 UTC 时间换算为北京时间，不直接当本地时间展示。
- “未提供截止时间”单列，不称为解析失败，也不推断没有截止要求。
- 同一批真实数据重复检查没有产生重复新增或变更。
- 部分课程失败保留该课程历史，恢复后不制造一批虚假新增。
- 报告写入失败时不提交新的去重基线。
- 跨站分页和重定向被拒绝，分页上限不能静默截断结果。

## 7. 邮件验证与当前未完成项

测试邮件通过连接器发送，使用者确认收件。这证明本次邮件链路可用，不证明计划任务会在指定时刻运行。

周五全量、周日增量已确定。定时触发尚未启用，也未验证长期会话存续、离线恢复或自动失败告警。现有本地任务脚本与应用邮件连接器不是同一个运行环境，需要单独衔接。

当前相关回归测试为 25 项通过；真实扫描、重开认证、真实数据去重及人工收件确认另行作为运行证据，未以测试数量代替端到端结论。

## 8. 发布原则

本轮只更新项目说明、开发记录及两份文档对应的发布清单校验值。公开记录保留早期判断被推翻的原因，不保留个人数据，不上传实现源码。

仍待验证：计划触发、定时运行身份与凭据访问、邮件失败后的处理、长期运行稳定性，以及 Assignments 之外的任务覆盖。没有经过验证的能力不写作已完成。
