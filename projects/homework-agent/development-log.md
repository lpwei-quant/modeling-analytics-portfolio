# 开发过程记录

记录这个项目的推进顺序、当时的判断依据，以及踩到的坑。结论性的设计说明见
[项目说明](README.md)。

## 第 1 步 · 环境与机制核实

动手写代码之前先确认两件事能不能成立，因为方案完全建立在它们之上：

1. **能否驱动浏览器**——机器上已安装的 Chrome 可以被无头驱动并读取页面内容，
   不需要额外下载浏览器内核。
2. **登录状态能否跨运行保留**——用一个本地 HTTP 服务下发会话 cookie，
   关闭浏览器后重新启动一个全新进程，**会话仍然存在**。

第 2 条决定了"每周自动运行"是否可行：如果每次都要重新登录，方案就不成立。
当时验证通过的是一条临时用例，现已固化为仓库外的回归测试。

> 依据：这两条都是实测结论，不是推断。第 1 步完成时，后端还没有接触过任何真实校园站点。

## 第 2 步 · 先做与平台无关的核心

当时还不知道学校用的是什么平台，但"时间解析、去重、报告"这三件事与平台无关，
于是先把它们做出来并用测试锁住：

- 时间解析覆盖：绝对日期、中文年月日、只有月日、相对日、倒计时、星期表述、
  无截止时间、无法识别。其中"缺年份/缺时刻"的推算单独标注为假定，
  完全无法解释的单独列出。
- 去重与变更识别：同一批数据连续跑两次，第二次必须"新增 0、变更 0"；
  截止时间改动必须识别为**变更**而不是新增。
- 报告：按紧急程度分档的中文清单；已完成作业不参与"新增/变更"计数。

这一步的价值在后一步体现出来：换成官方 API 之后，这三块逻辑一行没用改。

## 第 3 步 · 站点侦察，然后改路线

对学校站点只做了只读侦察，结论直接推翻了原定方案：

| 观察 | 结论 |
| --- | --- |
| 教学门户首页是自建站点，接口路径返回中文 404 | 门户不是课程平台本体 |
| 平台接口返回 `Bearer realm`、平台专有响应头与限流头 | 课程平台是 Canvas，且 API 可用 |
| 登录页跳转到统一身份认证中心 | 登录走 CAS，不是平台自有密码 |
| 本机直连返回"需要授权"而不是超时 | 不需要代理即可访问 |

**路线变更：** 从"浏览器抓页面"改为"官方 API + 个人访问令牌"。理由是 CAS 登录
必然牵扯学校密码与二次验证，模拟登录既不安全也不稳定；而官方令牌方案不接触密码，
且可以随时撤销。

浏览器会话模式没有删除，作为备用方案保留。

## 第 4 步 · 适配器与两种运行模式

- 适配器只做只读调用：校验凭据 → 分页读课程 → 按课程读作业与提交状态。
- 用**本地模拟的 Canvas 服务**验证适配器逻辑（分页、未发布过滤、状态判定、令牌校验），
  因此这部分在拿到真实令牌之前就已经可测。
- 增加增量模式：只输出相对上次检查的新增/变更，外加 3 天内截止的事项，
  避免周日重复推送整份清单。
- 定时任务：周五全量、周日增量，共享同一份历史状态，带开机补跑与运行日志。

## 踩到的坑

记录这些是因为它们都属于"看起来对、其实错"的类型：

1. **`unsubmitted` 被判定成已提交。** 平台的未提交状态字符串里含有 `submitted` 子串，
   用普通子串匹配会把"没交"判成"已交"——这是会导致漏交的严重错误。
   改用词边界匹配，并补了专门的回归测试。
2. **UTC 时间直接当本地时间显示。** 平台返回的是带时区的标准时间，
   必须显式换算，否则会出现"截止时间差 8 小时"这种最不容易察觉的错。
3. **"未传参数"覆盖掉默认值。** 配置合并时把 `undefined` 也一起合并，
   导致默认值被清空。已改为过滤掉未传的字段。
4. **示例数据污染真实历史。** 用示例适配器试跑会写进真实的状态文件，
   使第一次真实运行出现"大量作业消失"的假象。已让示例走独立状态文件。
5. **文档里的本机绝对路径。** 发布校验会拦截指向本机用户目录的绝对路径，
   公开文档必须改用相对路径——这反过来也保护了隐私（连"举例"都会被拦下）。
